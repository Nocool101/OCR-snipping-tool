# 06: 自定义提问输入框

**What to build:** **结果窗口**底部内置一个输入框，自己写一句指令（如「这段代码有什么问题」），回车后连同当前**文本**一起交给**模型**，答案流式显示在下半区。

**Blocked by:** 03、05

**Status:** ready-for-agent

- [x] 结果窗口底部有输入框，可输入任意指令
- [x] 回车即发送，指令与当前文本一并交给模型
- [x] 答案在下半区流式显示，与动作答案共用同一块渲染区
- [x] 输入框在请求进行中禁用或忽略重复回车，避免并发请求
- [x] `PromptBuilder` 有自动化测试：自定义提问把用户指令并入，且文本作为被处理内容

**Comments**

真机验证（真实 opencode-go 端点）：编辑器内容为「苹果 3 元，香蕉 5 元，一共 8 元。」，提问「一共多少钱？」→ 答案「8 元」；再问「香蕉多少钱？」→「5元」。回车触发、请求期间输入框禁用、结束后恢复、空问题只提示不请求，均符合预期。

`Action.ASK` 加入枚举（值即「自定义提问」，用作状态栏文案），但**不进 `ACTION_ORDER`**——它由输入框触发而非按钮。

代码审查（Standards / Spec 两轴）后修复：

- `perform(Action.ASK, text)` 漏传问题时**静默生成「问题：」加空行**发给模型——改为抛出 `ValueError`，并加测试。
- 结果窗口两处重复的「没有可处理的文字」守卫——抽成 `_processable_text()`。
- 答案区占位文字仍写「翻译、总结、表格转换」，漏了自定义提问——补上。
- `_run(action, start)` 的 `start` 参数改名 `start_stream`，避免与 `_run_action`/`_run_ask` 混淆。

**刻意保留（记录备查）**

- 输入框是单行的 `QLineEdit`，无法输入多行指令。票面要求「回车即发送」，单行与之一致；若以后要长指令，需换多行控件并改用 Ctrl+Enter。
- ASK 在 `perform` 里单独分支，其余动作走 `_ACTION_INSTRUCTIONS` 字典——两种机制并存。因为 ASK 需要额外的 `question` 参数，用一个统一签名反而要给另外三个塞无用参数，故保留分支。
