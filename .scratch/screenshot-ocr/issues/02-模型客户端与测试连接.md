# 02: 模型客户端 + 设置里的「测试连接」

**What to build:** 与**模型**通信的那一层打通，并在**设置**窗口里给一个「测试连接」按钮——用当前填的配置真发一次请求，成功或失败当场看得见。这样「与模型对话」这条链路可以脱离截图单独验证。

**Blocked by:** 01（设置与配置持久化）

**Status:** ready-for-agent

- [x] 设置窗口有「测试连接」按钮，点了用当前配置发一次纯文字请求
- [x] 成功时显示模型的简短回答，失败时显示失败原因
- [x] 客户端以流式方式接收文字（`stream: true`），能逐块取出增量文本
- [x] 请求使用配置里的接口地址、API Key、模型名
- [x] 缺 Key、网络错误、HTTP 错误码、超时被区分为可分类的失败
- [x] 客户端有自动化测试：起本地假 HTTP 服务，断言请求形状（基址、鉴权头、模型名）与 SSE 增量的解析

**Comments**

代码审查（Standards / Spec 两轴）后发现并修复：

- 空响应被判为「连接成功」——现改为「连接失败：模型返回了空内容，请检查接口地址与模型名」。
- `data:` URL 一律硬编码 `image/png`——现按magic bytes 嗅探 jpeg/gif，默认 png。
- `_ConnectionTest` 原以对话框为 parent，测试进行中关闭对话框会「Destroyed while thread is still running」崩溃——现不设 parent，用模块级集合持有引用直到 finished。
- `run()` 原只捕 `ModelError`，其他异常会让按钮永久禁用——现捕 `Exception` 并回报。

未采纳（记录备查）：`base_url`/`api_key`/`model` 作为 Data Clumps 未抽成独立值类型；`_parse_events` 对畸形 SSE 行静默跳过（保留，兼容 SSE keep-alive）。

**尚需人工验证**：用真实 API Key 点一次「测试连接」。自动化仅覆盖本地假服务。

**实测排查（真机）**

首次用真实配置点「测试连接」得到 `403` + 一段 Cloudflare HTML，两个原因：

1. `urllib` 默认 `User-Agent: Python-urllib/3.14` 被网关机器人防护拦截（Cloudflare error 1010）。已修：客户端固定发送 `screenshot-ocr/0.1 (OpenAI-compatible client)`，并加了回归测试。
2. 填的接口地址 `（某 OpenAI 兼容端点）` 是 opencode 内部路由网关，要求每个请求带 `x-opencode-session` 头（换成正常 UA 后返回 400 `MissingSessionID`）。它不是通用 OpenAI 兼容端点，**不适用于本工具**。

正确用法（智谱官方文档核对过）：

- 接口地址 `（某 OpenAI 兼容端点）`
- 模型名 `某视觉模型`（智谱自有模型），或免费视觉模型 `某视觉模型` / `某视觉模型`
- API Key 从 某平台 申请

智谱文档「图像理解」示例的请求体与本客户端的构造完全一致（`type: text` + `type: image_url` + `data:image/jpeg;base64,...`），图片识别链路无需改动。
