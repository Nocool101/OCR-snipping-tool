# 08: 历史记录

**What to build:** 托盘菜单里能回看本次运行识别过的记录（最近若干条，如 20 条），点一条能重新看到那次的**文本**。记录只在内存里，关掉程序即清空。

**Blocked by:** 03

**Status:** ready-for-agent

- [x] 每次识别都把文本追加进内存历史
- [x] 托盘菜单有「历史」入口，列出最近若干条（带时间与文本开头）
- [x] 点历史某一条能打开结果窗口显示那条文本
- [x] 历史超过上限时淘汰最旧的
- [x] 程序退出后历史不落盘，重启为空
- [x] `AppController` 有自动化测试：历史按上限淘汰、顺序正确

**Comments**

**设计**：托盘每次识别都会新建一个结果窗口（因而新建一个 `AppController`），历史若放在控制器里就会随窗口丢弃。因此把历史抽成独立的 `History` 对象，**由托盘持有一份**，注入给每个控制器共用。`History` 只存在内存里，不落盘。

**真机验证**（真实 opencode-go 端点，两次识别）：

- 启动时历史为空、菜单显示「（本次运行还没有记录）」且不可点。
- 识别「AAA 111」再识别「BBB 222」→ 历史两条，最新在前（`BBB` 在 `AAA` 之前）。
- 菜单列出两条，形如 `14:50:39  BBB 222`（时间 + 文本开头）。
- 点较早那条 → 新开结果窗口显示 `AAA 111`，状态「来自历史记录」，且**不发起任何请求**。

**代码审查（Standards / Spec 两轴）后修复**

- **真 bug**：`show_text` 没有解除编辑器的只读——打开的历史文本无法编辑、也无法对其做动作。已在冒烟里加断言并修正。
- `show_text` 顺带清空答案区、复位 `_last_attempt` 与重试按钮，使其在被复用的窗口上也安全。

**了结一笔旧账**：票 05 记录的父规格冲突（`spec.md` 原文「连续动作是追加而非覆盖」）在本票定案并**已回改 `spec.md`**——动作的答案在结果窗口里是**覆盖**显示；「追加」只体现在**历史**上。

**刻意保留（记录备查）**

- `Recognition.label()`（时间格式 + 24 字预览）放在 `history.py` 里，严格说是展示逻辑进了领域模块。这样做是为了让格式可被测试；若要更纯，应移到托盘的呈现层。
- `AppController(client, history=None)` 缺省时自建一份历史——语义上「这个控制器有私有历史」是成立的，但**忘记传共享历史会静默变成空菜单**。托盘的接线已由冒烟覆盖（菜单确实列出条目），故保留缺省值以免所有测试都要显式构造。
