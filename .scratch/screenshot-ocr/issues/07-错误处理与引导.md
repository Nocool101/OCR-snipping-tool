# 07: 错误处理与引导

**What to build:** 把失败变成看得懂的话。没配 API Key 就用**热键**截图时，直接引导打开**设置**窗口；网络失败或**模型**返回错误时，在**结果窗口**里给出说清原因的提示，而不是永远转圈。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 未配置 API Key 时触发识别，直接打开设置窗口并提示需要先配置
- [ ] 网络不通时，结果窗口显示「网络错误」类提示，可重试
- [ ] 模型返回错误（鉴权失败、模型名不存在、限流等）时，提示里体现原因
- [ ] 任一失败都不会让程序卡住或崩溃，窗口仍可关闭
- [ ] `AppController` 有自动化测试（模型客户端用假实现抛各类失败）：缺 Key、网络错误、模型错误被正确分类

**Comments**

**从 02 带过来的已知缺口（本票处理）**

SSE 响应体被**干净地**截断时（服务端正常 FIN 而非 RST），`urllib` 的逐行迭代会静默结束——客户端无法区分「正常结束」与「只收到半截」。表现为用户看到一个**不完整却没有报错**的答案。云端偶发断连时这是真实存在的（02 里观测到约 10% 的连接失败率，重试已覆盖大部分，但断在流中途时重试也无能为力）。

可能的解法：OpenAI 兼容协议以 `data: [DONE]` 标记结束，因此「读到 EOF 却没见到 `[DONE]`」即为截断，可据此报错。但某些兼容服务可能不发 `[DONE]`，贸然强制会让本来能用的供应商报错——需要先确认目标端点（本项目的 opencode-go 端点是发的）。是否采用、以及是否在提示里加「可重试」，留到本票决定。
