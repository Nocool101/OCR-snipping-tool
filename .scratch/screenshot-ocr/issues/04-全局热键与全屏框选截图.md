# 04: 全局热键 + 全屏框选截图

**What to build:** 按下**热键**（默认 `Ctrl+Alt+O`）进入截图模式：整个虚拟桌面（含多显示器）覆盖半透明遮罩，拖框选中区域的画面是亮的，松开鼠标即把该**截图**送入第 03 条已有的识别链路。按 `Esc` 取消。进入截屏前先隐藏本工具的窗口。

**Blocked by:** 03

**Status:** ready-for-agent

- [x] 按 `Ctrl+Alt+O` 进入截图模式，覆盖全部显示器（单屏已验证；多屏未验证，见下）
- [x] 遮罩半透明，拖出的选区是亮的，能看清框了哪块
- [x] 松开鼠标立即开始识别，无需二次确认
- [x] 按 `Esc` 退出截图模式，不产生任何识别
- [x] 截图模式期间本工具自身窗口不可见，不会截到自己
- [ ] 在缩放不为 100% 的显示器与多显示器布局下，框选区域与实际截取内容一致 —— 单屏 125% 已验证；多屏/混合缩放未验证
- [x] 热键注册失败（被别的软件占用）时给出提示并引导去**设置**改键
- [x] 截出的图片可直接交给 `AppController` 识别（与剪贴板路径共用同一入口）

**Comments**

**方案**：按热键时先抓下整个虚拟桌面作为**冻结画面**，遮罩画的就是这张图；框选直接从冻结图按比例裁剪。这样遮罩自己不可能被截进去，也没有"遮罩尚未消失就抓屏"的时序竞争。

**真机验证（单屏，1536×864 逻辑 / 1920×1080 物理 / 125% 缩放）**

- `grab_desktop()` 返回 1920×1080（设备像素）。
- 合成鼠标事件拖框 100,100 → 600,300（逻辑 501×201）→ 裁剪出 626×251 设备像素，比例正好 1.25。
- 整条链路：热键 → 遮罩 → 框选 → 识别 → 结果窗口「识别完成」，识别内容与屏幕上该区域的实际内容一致。
- 区域无文字时模型按指令返回「（未识别到文字）」。
- 热键冲突：同一组合键用第二个 id 注册返回 `False`。
- `Esc` 取消不产生识别，遮罩正常关闭。

**未验证 / 已知限制（如实记录）**

- **多屏与混合缩放未验证**：`grab_desktop` 用主屏的 `devicePixelRatio` 统一拼接所有屏幕，副屏若缩放不同会被重采样，选区坐标可能不一致。本机只有一块显示器，无法验证。规格已把此项列为"最容易出错、需真机验证"。
- 系统通知被关闭时气泡提示不可见——因此托盘 tooltip 也会带上热键注册状态。

**代码审查（Standards / Spec 两轴）后修复**

- `_canonical_key` 用 `str.isalnum()`（Unicode 友好），「Ctrl+我」会被当成合法热键并产生非法虚拟键码——改为只接受 `A-Z0-9`。
- `combination_from` 接受裸键（如只按 `O`）生成「O」，设置框显示 `O` 却在保存时静默回落默认值（显示与保存不一致）——改为要求至少一个修饰键。
- 遮罩若被非 `Esc`/非框选的方式关闭（如 Alt+F4），托盘里的引用不会清空，之后热键将永久失效——遮罩新增 `finished` 信号，关闭即清空。
- 热键连按两次会开出两个遮罩——`_overlay` 只在 150ms 定时器之后才赋值，加 `_capture_pending` 立即占位。
- `grab_desktop()` 抛异常时已隐藏的窗口不会恢复——改用 `try/finally` 保证恢复。
- 启动时「已在后台运行」气泡会盖掉热键注册失败提示——改为仅在注册成功时才弹。
- 两处重复的空图提示抽取为 `_warn`。
- `capture.to_size` 的返回类型标注写成 `Rect`（4 元组）实为 2 元组——修正；`crop_rect` 参数名 `widget/image` 实为尺寸——改名。

**刻意保留（记录备查）**

- `hotkey.py` 中修饰键信息分散在四张并行表里（别名、顺序、Win 位、Qt 标志），新增一个修饰键要改四处。当前只有四个修饰键且已被测试覆盖，暂不收拢。
- 热键注册失败只发提示与 tooltip，不自动弹设置窗口——避免启动即打断。若后续觉得提示不够显眼，可在 **07 错误处理**里统一处理。
