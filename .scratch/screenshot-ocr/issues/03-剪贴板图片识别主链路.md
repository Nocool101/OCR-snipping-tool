# 03: 剪贴板图片识别主链路

**What to build:** 第一条真正跑通的**识别**竖切。托盘菜单点「识别剪贴板图片」，程序读剪贴板里的图片，交给**模型**识别，**结果窗口**弹出，**文本**流式逐字出现，可以一键复制。这条链路先绕开截图与热键，把「图片 → 文字 → 窗口」验通。

**Blocked by:** 01、02

**Status:** ready-for-agent

- [x] 托盘菜单有「识别剪贴板图片」项
- [x] 剪贴板有图片时：结果窗口弹出并显示「识别中…」，随后文本流式出现
- [x] 剪贴板无图片时：给出明确提示，不弹空窗口
- [x] 识别指令要求逐字提取图中全部文字、保留换行、除文字外不加解释
- [x] 结果窗口上半区是可编辑的纯文本，底部有「复制」按钮（流式期间临时只读，识别完成或失败后恢复可编辑）
- [x] 复制按钮把当前（可能已编辑的）文本放进剪贴板
- [x] `AppController` 有自动化测试（模型客户端用假实现）：流式片段正确拼接、文本可被替换为编辑后的值
- [x] `PromptBuilder` 有自动化测试：识别指令包含「逐字提取/保留换行/不加解释」的约束

**Comments**

真机端到端验证（真实 opencode-go 端点）：Qt 渲染一张含「你好，世界！OCR 测试 12345」的 PNG 放进剪贴板 → 点「识别剪贴板图片」→ 窗口显示「识别中…」→ 流式完成后文本逐字正确 → 复制到剪贴板正确 → 关窗后从窗口列表回收。无图片时只弹托盘提示，不弹空窗口。

代码审查（Standards / Spec 两轴）后修复：

- `_RecognitionWorker.run()` 原只捕 `Exception`，`BaseException` 会让界面永久卡在「识别中…」且只读——改为 `except BaseException / else`，保证终态信号必然发出。
- 失败时 `controller.text` 不更新（编辑值契约失效）——现在失败路径同步编辑器内容到控制器。
- `window.destroyed.connect(lambda: self._forget(window))` 在 C++ 对象已删除后做成员比较，会抛 `RuntimeError`——改为窗口在 `closeEvent` 里发 `closed` 信号（此时对象仍存活）。
- `_describe` 与「线程保活集合」在 `settings_window` / `result_window` 两处重复——抽到 `qt_support.py`（`describe` / `keep_alive`）。
- 流式期间每个片段都经 `textChanged → toPlainText()`，O(n²)——加 `_streaming` 守卫。

**刻意的偏离（记录备查）**

- 规格称该组件为 `PromptBuilder`，实现为 `prompt_builder.py` 模块级常量 `RECOGNIZE_INSTRUCTION`。本票只需识别一条指令，尚无理由引入类；待 05 加入四个动作的指令时再考虑成形。
- 结果窗口在流式期间临时只读：避免用户编辑与流式追加相互覆盖。识别完成/失败后即可编辑。
- `AppController` 尚无「执行动作」与「历史」——分别属于 05/06 与 08。
- 未配 API Key 时未引导打开设置——属于 07。
