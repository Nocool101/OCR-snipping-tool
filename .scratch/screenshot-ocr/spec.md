# 截图识别（screenshot-ocr）

Status: ready-for-agent

## Problem Statement

我需要从屏幕上读文字——外文资料、图片里的段落、软件界面里的报错、视频字幕——但现在只能靠肉眼抄，或者先截图再手动上传到某个聊天网站，慢且打断思路。Windows 也没有一个「按个热键框一下，文字就出来了，顺带还能翻译总结」的顺手的工具。

## Solution

一个常驻托盘的 Windows 个人工具。按 `Ctrl+Alt+O` 进入截图模式，屏幕变半透明遮罩，拖框选中要识别的区域，松手后选区截图交给多模态大模型识别。识别出的**文本**出现在**结果窗口**上半区（可编辑、可一键复制），下半区是**动作**的回答，流式逐字显示。四个动作：翻译成中文、总结、表格转换、自定义提问。模型、热键、开机自启在**设置**里配置。

## User Stories

1. 作为用户，我想在任意界面按下全局热键 `Ctrl+Alt+O` 就进入截图模式，这样我不用先切换窗口或找工具。
2. 作为用户，我想截图模式覆盖整个虚拟桌面（含多显示器），这样我在哪块屏幕看到的内容都能截。
3. 作为用户，我想在截图模式里看到半透明遮罩、拖出的选区是亮的，这样我能看清自己框了哪块。
4. 作为用户，我想松开鼠标就立刻开始识别，不用再点一次确认，这样操作最短。
5. 作为用户，我想按 `Esc` 取消截图模式且什么都不发生，这样我误触热键时能退出。
6. 作为用户，我想识别开始时结果窗口就弹出来并显示「识别中…」，这样我知道它在干活。
7. 作为用户，我想识别结果逐字流式出现，而不是干等几秒，这样等待不焦虑。
8. 作为用户，我想结果窗口里识别出的文字可以编辑，这样模型偶尔认错字我能自己改。
9. 作为用户，我想结果窗口里有一个「复制」按钮，这样我能把文本贴到别处。
10. 作为用户，我想点「翻译成中文」把当前文本翻成中文，答案流式显示在窗口下半区。
11. 作为用户，我想点「总结」得到当前文本的几句话概括。
12. 作为用户，我想点「表格转换」把截图里的表格变成 Markdown 表格，便于贴进文档。
13. 作为用户，我想在结果窗口底部输入框里自己写一句指令（如「这段代码有什么问题」），回车后连同文本一起发给模型，答案回到窗口。
14. 作为用户，我想答案区渲染 Markdown（粗体、列表、代码块），这样大模型的输出看着整齐。
15. 作为用户，我想动作的答案和识别文本分开显示（上纯文本、下渲染），这样我不至于把答案误当成原文。
16. 作为用户，我想在托盘菜单里打开设置，配置模型的接口地址、API Key、模型名。
17. 作为用户，我想在设置里修改全局热键，这样默认热键和别的软件冲突时我能换。
18. 作为用户，我想在设置里开关「开机自启」，默认关闭，由我决定。
19. 作为用户，我想设置自动保存，下次启动还在，不用重填 API Key。
20. 作为用户，我想在没配 API Key 时就按热键去识别时，被直接引导打开设置窗口，而不是看到一个看不懂的报错。
21. 作为用户，我想网络失败或模型返回错误时看到一个说清原因的提示，而不是永远转圈。
22. 作为用户，我想在托盘菜单里回看本次运行识别过的记录（最近若干条），这样刚才那条我忘了复制还能找回。
23. 作为用户，我想历史记录只存在内存里、关掉程序就清空，这样不留下隐私残留。
24. 作为用户，我想托盘菜单里有「退出」，这样我能真正关掉它。
25. 作为用户，我想托盘图标双击能打开最近一次结果窗口或设置，这样我不必重截。
26. 作为用户，我想程序是单个 exe、双击即用、无需装 Python，这样换机器也能带走。
27. 作为用户，我想识别时工具自己的窗口不出现在截图里，这样不会自己套自己。
28. 作为用户，我想同一次识别的文本可以被连续做多个动作（先翻译、再总结），且每次动作都基于当前编辑后的文本。

## Implementation Decisions

**模块划分**

- `SettingsStore` —— 负责**设置**的读写。配置文件为 JSON，位置在用户 AppData 下的应用目录；字段：模型接口地址、API Key、模型名、热键、是否开机自启。缺失文件或字段用默认值兜底，损坏文件不崩溃、回落到默认值。
- `ModelClient`（接口）—— 与模型交互的唯一抽象：输入「图片字节 + 指令」，输出文字流（增量片段）。
- `OpenAICompatClient`（`ModelClient` 的实现）—— 通过 OpenAI 兼容的 `chat/completions` 接口，以 `stream: true` 流式取回，图片以 base64 的 data URL 放进消息内容里。
- `PromptBuilder` —— 生成各场景的指令：识别指令要求逐字提取图中全部文字、保留换行、除文字外不加任何解释；四个**动作**各有一条指令（翻译成中文、总结、表格转换、由用户指令拼装的自定义提问）。
- `AppController` —— 行为中枢，不依赖 Qt：`识别(图片字节) → 文本`、`执行动作(动作, 文本) → 流`，并维护本次运行的**历史**（有上限，如最近 20 条）。
- `CaptureOverlay`（Qt）—— 全屏半透明遮罩 + 拖框选区；松开即产出截图字节；`Esc` 取消。
- `ResultWindow`（Qt）—— 上半区可编辑纯文本、下半区渲染 Markdown 的答案、底部**自定义提问**输入框、复制/翻译/总结/表格转换按钮。
- `SettingsWindow`（Qt）—— **设置**表单。
- `TrayApp`（Qt）—— 托盘图标与菜单（设置、历史、退出）、全局**热键**注册、把上述部件接起来。
- `main` —— 入口，单实例。

**接口契约**

- 识别与动作都走同一条「图片（可选）+ 指令 → 文字流」的路径：识别带图片，动作只带文本。
- `ModelClient` 的错误对控制器暴露为可区分的失败（缺 Key、网络错误、模型报错），而不是笼统异常。
- 流式协议：`OpenAICompatClient` 解析 SSE 的 `data:` 行，逐块产出增量文本，遇到结束标记停止。
- **模型**只有一个，识别与所有动作共用它；需支持图片输入（见 `docs/adr/0001-用多模态大模型替代传统-ocr.md`）。

**交互细节**

- 默认热键 `Ctrl+Alt+O`；注册失败（被占用）时给提示并引导去设置改键。
- 进入截图模式前隐藏本工具窗口，避免截到自己。
- 结果窗口的 Markdown 渲染只影响下半区答案；上半区始终是纯文本编辑框。
- 历史仅内存保存，仅可回看，不做持久化（隐私取舍）。
- 每次动作都以「当前编辑后的文本」为输入，允许对同一文本连续做多个动作。

**打包**

- Python + PySide6；以 PyInstaller 打成单文件/单目录 exe，作为最终交付形态。

## Testing Decisions

**什么算好测试**：只测外部可观察的行为，不测内部实现细节——给定输入与假模型，断言控制器产出的文本流、历史变化、错误分类；给定假 HTTP 服务，断言客户端发出的请求形状与它对返回内容的解析。测试里不启动 Qt、不注册真热键、不抓真屏幕。

**要测的模块与场景**

- `SettingsStore`：默认值、写入后读回、字段缺失、文件损坏时不崩溃。
- `PromptBuilder`：识别指令包含「逐字提取/保留换行/不加解释」的约束；四个动作各自产出预期指令；自定义提问把用户指令并入。
- `AppController`（模型客户端用假实现）：流式片段被正确拼接、历史按上限淘汰、缺 Key/网络错误被正确分类向上传递。
  **（2026-09-24 修订）** 原文此处写作「连续动作是追加而非覆盖」，该表述含糊。经 05 与 08 两票定案：**动作的答案在结果窗口里是覆盖显示的**（每次动作清空答案区，见票 05 的 Comments）；**「追加」只体现在历史记录上**——每次识别都把文本追加进历史（见票 08）。
- `OpenAICompatClient`（起本地假 HTTP 服务作为第二个接缝）：请求体含基址/鉴权头/模型名/图片 data URL；正确解析 SSE 增量；HTTP 错误码与超时被映射为可分类的失败。

**测试先例**：仓库目前无任何测试，本规格即为先例——用 pytest，测试文件与被测模块并列，假实现（fake `ModelClient`、本地假 HTTP 服务）写在测试内。

## Out of Scope

- 任何传统 OCR 引擎（Windows 自带 OCR、PaddleOCR、云 OCR API）——见 ADR-0001。
- 离线识别能力。
- 多模型配置（识别用一个、处理用另一个）。
- 历史记录的持久化、搜索、导出。
- 除 Windows 外的平台。
- 自动更新、安装程序、代码签名。
- 截图后的图像编辑（标注、裁剪微调、旋转）。
- 快捷键之外的触发方式（托盘点击截图等）。
- Windows 自带 OCR 语言包相关的多语言识别优化。

## Further Notes

- 交付形态是个人自用工具，不做安装包，只出 exe。
- 识别的质量与可用性取决于所选**模型**是否具备视觉能力；设置里应允许填任意 OpenAI 兼容服务（如各家的视觉模型）。
- 高 DPI 与多显示器下的坐标换算是本项目最容易出错的地方，实现时需在真实的多屏/缩放下手动验证。
- 结果窗口的行为属于「必须亲眼看」的部分，实现后需人工走一遍：截图、流式出现、四个动作、错误提示。
