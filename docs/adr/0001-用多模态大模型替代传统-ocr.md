# 用多模态大模型替代传统 OCR

截图识别不接任何传统 OCR 引擎（Windows 自带 OCR、PaddleOCR、云 OCR API），而是把截图直接交给多模态大模型（OpenAI 兼容接口，视觉能力由模型提供）取字。

理由是这条链路一份依赖都不多背：不需要打包几百 MB 的本地模型和运行时，不需要另注册一家 OCR 服务的账号与计费，识别与后续动作（翻译、总结、表格转换、自定义提问）共用同一个模型、同一份设置。代价是识别必须联网、按 token 计费，且识别质量取决于所选模型的视觉能力——这些代价对本项目（Windows 个人自用工具）可以接受。

## Considered Options

- **Windows 自带 OCR（Windows.Media.Ocr）**：免依赖、免费、离线，但中文质量一般，且从 Python 调用麻烦，还会引入一套与"大模型"并行的第二条识别链路。
- **PaddleOCR 本地模型**：识别质量最好、离线，但要随程序打包数百 MB 的模型与运行时，对一个个人工具过重。
- **云 OCR API**：质量好，但需要单独开通、单独付费、单独配 Key，与已有的"模型设置"重复。

## Consequences

- 识别结果强依赖网络与模型本身；无网或模型无视觉能力时功能不可用。
- 设置里的"模型"必须支持图片输入，否则识别失败。
